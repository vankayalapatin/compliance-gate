# ComplianceGate — Decisions (Final)

Each entry: decision plus reason. Full record: docs/DATA-MODEL.md plus docs/COMPANY-DATA.md. Early-demo history: docs/archive/ (frozen).

1. Single C# Blazor app, all C#. Reason: solo plus 10 days favors one codebase and one demo URL.
2. Mini-ERP is its own module with its own tables; agent and compliance go through a data-only adapter. Reason: a future D365/NetSuite connector can replace the adapter without touching agent logic.
3. Adapter reads raw ERP only (BOM not explosion, stock, open POs, SOs, vendors, documents, history, ASN, receipts, invoices). Reason: explosion, shortfall math, and invoice matching belong in the agent and must be tested there.
4. Adapter writes: create PR, submit for approval, create PO, update SO status, block vendor, add PO note, post receipt, set/release hold, create invoice plus record match result. Reason: covers shortfall to pay including blocks with no logic leaks.
5. ERP hold carries reason code plus rule id plus case link; photos and explanations stay agent-side. Reason: ERP stays lean while evidence stays citable from the case.
6. Screening snapshots live compliance-side, never in ERP; model never fetches lists at runtime. Reason: sanctions and UFLPA data are compliance inputs, and replays must run offline from cache.
7. Compliance shape: versioned C# records from JSON decide; Muse explains and cites rule id. Reason: demo needs deterministic blocks with readable explanations.
8. Every compliance rule traces to a real public regulation with stored source; AP controls stay separate. Reason: each block must cite authority, and duplicates plus price variance are controls, not compliance.
9. Packs independent and pluggable per industry/part. Reason: a new part pack can be added or swapped later.
10. Dock is photo-only and photos never set quantities; ASN-missing cartons go to human review. Reason: a carton photo cannot reliably count.
11. BAT-LI-05 damage never auto-quarantines; human decides from Muse crops. Reason: photo damage judgment is too risky to automate. Fallback recorded: if no damaged image by build day, BAT-LI-05 drops to Tier 2 and review comes from the unclear carton.
12. ELEC-03 radio evidence removed. Reason: out of scope for this part story; keep the build small.
13. Tiering: Tier 1 fails in demo (CORP-02, BAT-LI-03, BAT-LI-05 conditional, ELEC-04); Tier 2 passes silently but shows in timeline and audit; Tier 3 documented only. Reason: four demo failures cover all gates without overload.
14. CORP-02 country-origin cap is the Tier 1 company rule; CORP-01 single-vendor cap is documented only. Reason: origin gives the cheaper-fails tradeoff; only one company cap fires. Both are fictional memo plus board minutes from a named approver, overridable only by logged exception.
15. Restricted-party screening SCR-01 enforced silently; UFLPA SCR-02 documented only. Reason: identity screening is mandatory background work, not demo drama.
16. Block-vs-warn: Tier 1 hard blocks; Tier 2 silent with ledger; limits, no-self-approve, and delegation are hard ERP refusals with delegate routing. Reason: money always stays behind a human.
17. Dock set: 4 images (3 pallet views plus 1 relabel reshot), Muse Image generates once offline, Spark reads every label, all results cached, upload for testing only. Reason: deterministic multi-side coverage with replayable cache.
18. ERP fields plus three surfaces (Decisions, Cases, Records) plus Policies and Audit, agent work labeled Created by agent. Reason: humans decide from evidence; ledgers stay plain.
19. Dataset: glasses BOM, critical battery plus auto-approved non-critical short, Vendor A fails origin, Vendor B wins and carries dock holds, Vendor C shows straight-through, five seeded people, AP inbox with duplicate plus bank-change plus missing-fields invoices. Reason: smallest seed that fires every gate plus SoD plus AP catches.
20. Simulation in scope (order webhook, supplier ACK/ASN/invoices, secured notification); live camera, video, voice, shipping, customer invoicing, scheduling, forecasting tools out; seeded forecast data in. Reason: simulate the chain without live dependencies.
21. Done checklist with partial pay, reshot resolution loop, delegate SoD, full audit, unit tests, offline reset and replay. Reason: everything is observable or tested.
22. 3-minute video per the approved scene order and times; rest proven by tests. Reason: fits the official limit and slows down only at the dock.
23. Stretch list gated until core Done means are met. Reason: protects the 10-day core.
24. Dock legibility backstop: if a pallet image is not readable by Spark after a few tries, switch to compositing labels and stop regenerating. Reason: generated carton text garbles often and credits cannot survive regen churn.
25. Composited labels come from seed data (carton id, part, PO, mark present or not); Spark read accuracy is measured against that ground truth. Reason: turns a demo risk into a measured accuracy claim judges remember.
26. Build in video order; Policies may stay thin. Reason: the scarcest resource is solo days, so the thinnest surface must be the one the video needs least.
27. RoHS/REACH (ELEC-01/02) apply to BAT-1; doc packs scope by item critical flag. Reason: the scenario seed requires both battery vendors to pass them, so BAT-1 scope is correct and the V-A/V-B rows are genuinely missing; the real scope bug was non-critical SCR-9 being evaluated against packs at all, fixed by ItemDto-gated not-applicable passes, with V-C fake n/a docs removed.
28. ERP-DESIGN §9 gaps 1-15 verified closed in current contracts plus EF Core build; gap 16 (credit memos, lot-level origin) stays design-only with vendor default country as origin of record. Reason: close the design loop on evidence, keep the contract surface minimal.
29. No dock-read DTO promotion: CartonRead stays compliance-internal, HoldDto carries rule id plus case link plus carton id. Reason: transcription is agent-side evidence per the adapter contract; a DTO adds surface without a consumer.
30. ELEC-04 extends to holds plus quarantine plus open reviews via a PrePayState DTO; queued for the next compliance batch. Reason: the current holds-only input under-reads the rule, but the change needs compliance tests, not a drive-by.
31. Rule thresholds migrate to versioned rule JSON; named C# consts stand for the POC. Reason: three sources require JSON-loaded config, but batch 1 shipped plain rules code; migrate with tests, not under merge pressure.
32. schema.md created as a thin lead-owned index pointing at the contract files and EF model. Reason: the contract rule cited a file that did not exist; an index cannot rot like a duplicated schema.
33. Gate.Web wired to the EF Core ERP (scoped adapter plus DbContext over data/erp.db, migrate at startup); the in-memory fake is unit-test-only. Reason: production bar requires the real ERP behind the app.
34. Image model pinned to muse-image-1.0, proven via one GET /models call. Reason: the 404 came from a chat-model fallback; the id is now discovered, not guessed.
35. generated_images/ is git-ignored tool scratch; the deliverable is assets/dock/. Reason: keep the base-image working files without polluting the repo.
36. Rule thresholds and caps live in per-pack JSON (Gate.Compliance/Packs/), loaded at startup with version validation; the engine takes overrides for trials. Reason: named consts made policy look like code; JSON plus a different-values test proves policy is data.
37. Dock labels build at ASN time for the ERP-minted PO: the image model applies each carton's label first, and any image whose Spark read mismatches the manifest falls back to compositing, with the path recorded per image. Reason: labels must follow the actual PO, AI text is tried before trusted, and image outputs plus reads cache by hash so replays cost nothing.
38. CTN-06 moved from IMG-01 to IMG-03 visibility; single-view coverage accepted for CTN-03/08/10/12 and CTN-11 stays absent (no sliver). Reason: the 6-face base cannot show 7 cartons, and 3 views hold ~19 face-slots against 22 needed for full double coverage; rules and targets unchanged, coverage honestly logged.
39. Dock reads carry class9_visible from Spark with Class9Required true for all BAT-1 cartons at scoring time. Reason: requirement is a part property from ground truth, visibility is the observation.
40. Images-edits calls carry image plus model plus prompt plus n only with per-request auth, and the label prompt avoids damage wording; golden result is IMG-04 AI-labeled with pallet views verified-fallback. Reason: the endpoint rejects mask and response_format, damage words trip the content filter, and multi-label pallet text does not survive field-by-field verification.
41. Voice input stays out: a supplier-voice scenario was considered and dropped. Reason: voice calls are where fraudulent actors most easily exploit AI agents (a faked supplier call requesting a bank change), so bank verification stays human-led — the verifier calls the number on file, never a number from the change request — with a what-to-ask checklist on the BankVerification decision.
42. Every external input accepts any valid input: Shopify orders, supplier ACKs, ASNs, invoices, dock photos. Reason: seed and demo files are one example each, not the contract; a path that only works for seeded data is fake completion, and the app must behave as production-grade software.
43. Spark drives the P2P flow through tool calling; CasePicker stays as the guard that blocks moves the case cannot make, and C# keeps ERP enforcement plus compliance verdicts. Reason: the project goal is an agentic buyer, and C#-only orchestration with model narration was backwards. This supersedes the batch-1 division for orchestration only: verdicts and controls still never come from the model, and every model write executes through a validated tool.

Judge review recorded with these decisions: top failure risk is generated label legibility, top schedule risk is the five-surface build, main credit burn is per-label Spark reads (read once, cache, develop against cache). Memorable moments: carrier-rejection opener, cheaper-vendor origin rejection, slowed-down dock with cited holds, partial pay with cited held amount, audit close.
44. Money approvals stay human with separation of duties: the agent drafts payments and routes a PaymentApproval decision, but only a human resolves it; the router excludes the requester, AP clerks, and every invoice approver, and prefers the payment-approver role. Reason: the agent must never approve its own money, and finance must differ from the invoice approver. Auto-approve thresholds apply to PR/PO only, never to invoices or payments.
45. Sourcing and payment tools stay single-step: screening records verdicts together, then Spark awards one passing vendor with its own reason, then creates the PO and submits it as separate steps; the pre-pay gate is a read-only check and drafting is its own step with human approval after. Reason: one tool doing several business steps hides choices from the transcript; each choice stays visible, validated, and replayable.
46. A case cannot finish while an invoice problem is open: unemailed AP problems route to a vendor query step, emailed-but-unresolved ones park for the clerk, and finish needs every review closed. Reason: resolving on paper while vendor money is still held would silently drop the problem; the human owns the close.
47. Dock eval 50: a 50-photo Spark/Glimmer eval with the oracle (answer-key.json) decided before any image was built; label problems (missing mark, wrong PO/part, smudged lot) are code-drawn and certain, Muse Image carries only scenes (10 text-free bases), Spark reads each final once with the shared prompt and caches by sha, and C# scores catches by problem type; 14 photographic crush/hide finals ship with a manual-check list. Reason: measures dock-read accuracy per failure mode on a reusable photo set a second model can read later, without spending credits on label-text regeneration.
48. Muse Image learnings (counts from assets/dock/build-record.json): close-up single-label AI edits verified 1/1 (IMG-04 reshot); pallet multi-label AI edits failed field-by-field verification 3/3 after one attempt each (IMG-01/02/03, "verify read mismatched the label manifest") and fell back to compositing; text-free base scenes generated first-try 2/2 for the demo pallet angles plus 10/10 for the eval50 scenes with no retries. Reason: the image model is reliable for scenes and single close-up labels but not for multi-label pallet text, so labels stay code-drawn and the model stays on scenes.
49. Dock eval hard: 30 pallet photos (5-6 cartons each, 170 cartons) as the hard tier next to the 50 close-ups; oracle problems decided before images, small rotated code labels on 6 text-free Muse pallet scenes (face centers measured by eye), one photographic subtle dent per dent base, one Spark read per photo scored per carton in code; read budget raised to 4000 max tokens after a 6-label read truncated twice at 2000. Reason: close-ups scored 50/50, so the eval needs realistic pallet density, and multi-label reads need output headroom.
50. Hard-tier label revision: the battery mark was redrawn in the style of the real handling mark (red hatched border, battery pictogram, UN plus contact line) with the Class 9 diamond removed so it is the only symbol, and every carton got a unique lot (LOT-HARD-<photo>-<slot>) after review showed a shared lot lets smudged reads copy neighbours; Spark re-read all 30 and rescored 170/170. Reason: a mark Spark can mistake for another symbol, and a lot it can copy unseen, measure nothing.
51. Tool-loop refusal steering plus three-strikes rule fallback: the turn prompt states the current step's goal in plain words and names exactly the tools offered that turn and no others, since models call remembered tools unasked; a call for an unoffered tool is refused with the legal set first, never coached on arguments it cannot use; three turns in a row with refused calls and no executed action, three identical no-action turns, or eight no-action turns of any mix hand the picked step to C# through the model-deferral path, logged on the timeline ("After three refused tries, ... ran by rule instead", with the trigger named). The split step deliberates over read facts, so only the refusal breaker applies there. At the split step the fallback is a single-vendor award to the cheapest passing vendor by ERP unit price (priceless passing vendors skipped, none priced refuses loudly); C# never invents a split. An executed action, a reads-only turn, or a deferred turn resets the count; payment keeps its two-turn rule. Reason: a live 1300 walk burned 50 turns calling award_supplier without arguments on the split step because argument errors hid the legality signal; the loop must steer, then finish by rule, never flail.
52. Pack versions are v1, v2, ... vN everywhere (packs, refusals, memo sentences, Governance); the CORP base ships v2 because MEMO-0001 published it from the v1 initial. Reason: dotted versions confused every surface, and the base pack is post-memo state so its version must say so.
53. Published rule packs take effect with no rebuild and no restart: the engine resolves the current pack set per evaluation (published files in the app data dir overlaid over the embedded bases, per pack), and the app publishes into git-ignored live data, never the source tree. Reason: a rule the company approved must enforce on the next check, and publishing into source would leak company decisions into the build.
54. Split creation order is mechanics: the verifier tries the proposed line order first, then every other order (all permutations up to four lines, else the reverse), and the first order in which every line passes becomes the plan's creation order; the POs create in that order. Reason: Spark kept cutting the CinderVolt line down (800 to 300) because CinderVolt-first breached while Meridian-first passed the same plan; a valid plan must never die on listing order.
55. Library dock scenes warn on read-back mismatch instead of failing the view build; only the live generated-scene path hard-gates on read-back. Reason: library labels are code-drawn so their content is certain and a mismatch is a reader miss (the Class 9 diamond rendered as an unreadable black blob and misread 4/4 on identical pixels); generated pixels stay gated because there the photo itself is uncertain. The dock check still judges every carton from the read, and unconfirmed cartons still go to a person.
56. No dock evidence means no payment: received quantity on ASN-declared cartons is payable only after the dock check completes with every carton verdict a pass. The match holds the quantity with "Awaiting dock check" and the ELEC-04 release gate refuses while its lots are pending; both are own-value like quarantine, never a whole-payment block, so accepted value still pays and partial pays still work. The platform reports passed cartons per invoice and the ERP intersects with its own ASN cartons, so no dock foreign keys enter ERP tables; lots with no ASN cartons declare nothing photographable and stay on the older three inputs. Reason: a receipt that was never photographed produced no hold, quarantine, or review, which was the pass state, so its invoices paid in full; the gate must see the missing check itself.
57. The dock counter offers only views recorded for the current cases, and restoring the saved data deletes the recorded views plus the image cache. Only bare file names are recorded, and the wipe skips anything else. Reason: a photo minted for an earlier shipment names the same cartons while showing other goods, and sending it holds the wrong cartons; unrecorded files stay on disk but are never offered.
58. The origin-cap share sentence shows for critical items only; on anything else the screening table's not-applicable reason stands alone, stored and live. Reason: the figures still ride the verdict, and rendering a share from them contradicted the passing verdict with a blocked outcome.
